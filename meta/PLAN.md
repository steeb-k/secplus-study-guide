# Security+ SY0-701 study kit — overview

Two repos, one site. The markdown study guide lives here; the practice site and the HTML guide live in the GitHub Pages repo.

  file per domain plus reference sheets:

  STUDY-GUIDE-FULL.md                        GENERATED by meta/build-full.py: everything in one file

  Style: meat-and-potatoes for a reader who already knows most of the material. Every file follows the official objective numbering
  (`## 1.2 Summarize fundamental security concepts`); every sub-bullet gets at least a one-line definition framed the way the exam tests
  it; tables for compare/contrast sets; `> **Exam tip:**` callouts for commonly confused pairs; each domain ends with "Most-tested
  distinctions". Each file carries a one-line AI-generated disclaimer that the site build strips.

## Exam model
CompTIA Security+ SY0-701: up to 90 questions, 90 minutes, scaled 100–900, pass 750. The site's final exam is 5 PBQs first (spread
across domains), then 85 MCQs by weight: D1 10, D2 19, D3 15, D4 24, D5 17 (`window.SEC_EXAM`). Scoring: single MCQ 1 point for the
right index; multi MCQ 1 point only for the exact set (no partial credit); PBQ partial credit = correct cells / total cells, counted as
one question-equivalent. `pct = points / total`; `scaled = 100 + round(pct * 800)`; pass = scaled ≥ 750.

## Practice app behavior
- **Routes:** `#/` home · `#/module/:d` module setup · `#/final` final setup · `#/drill` missed drill · `#/quiz` active session ·
  `#/results/:attemptId` · `#/history` · `#/settings`.
- **Home:** five domain cards (name, weight, bank size, last score, readiness badge), Final Exam card, Missed Drill card, footer nav
  History / Settings / Source, and a "Resume in-progress …" banner while a session exists.
- **Module setup:** count 10 / 25 / 50 / all; mode Practice (instant feedback with explanation after "Check") or Exam (feedback only at
  the end); "Include PBQs for this domain (up to 2)" on by default.
- **Final exam:** always Exam mode; 90:00 countdown top-right with Pause; the timer runs only while the page is visible and not paused
  (accumulated elapsed ms + `runningSince`), unless "Strict timer" is on in Settings; at 0 it auto-submits.
- **Selection:** per-question `seen` counts; draws prefer least-seen questions (random tie-break), then shuffle; option order shuffled per
  presentation, seeded by session id + question id so it is stable on reload; no repeats within a session.
- **Session UI:** counter `Q 12 / 25`, domain + objective tag in Practice mode only (Exam mode hides it like the real test), stem,
  options as large rows (radio or checkbox with a "Choose N" hint), Flag, Prev/Next, Review grid (answered / unanswered / flagged),
  Submit with an unanswered count. Keyboard: 1–6 select, F flag, ←/→ navigate, Enter check/next. Every change persists immediately.
- **Results:** percent, scaled score with pass/fail, per-domain table, weakest objectives, time used, full review with filters
  All / Missed / Flagged, objective links into the guide, "Retry missed", "Back to home".
- **Missed drill:** questions whose most recent result was wrong, filterable by domain, Practice mode; a correct answer removes one.
- **History:** attempts table (newest first); per-domain attempts, best, last-3 average and readiness badge (green when the last 3
  module attempts are all ≥ 83%, yellow when the last one is, red otherwise); final-exam summary. CSS bars, no chart library.
- **Settings:** export JSON, import (merge or replace), reset everything (confirm), strict timer, theme auto / light / dark.
- **Storage keys** (JSON, prefix `secplus.`): `version`, `session`, `attempts`, `qstats` ({qid: {seen, correct, wrong, lastCorrect,
  lastAt}}), `settings`; the guide adds `guide.last` and `highlights`.

## Specs and tests
- `QUESTION-SCHEMA.md` — bank formats and authoring rules; `DESIGN.md` — tokens, header, components; `GUIDE-SITE.md` — the HTML guide.
- Site tests, all of which must pass: `node tests/validate-bank.js`, `node tests/engine.test.js`, `node tests/guide-core.test.js`,
  `node tests/guide-ui.test.js` (headless Chromium), `bash tests/smoke.sh` for `index.html`, `guide/index.html` and `tests/dev.html`,
  `bash tests/guide-sync.sh`.
- After any markdown edit here: `python3 meta/build-full.py`, `python3 meta/build-site.py`, then the sync and smoke tests in the site,
  then commit both repos.
